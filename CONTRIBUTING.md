# Contributing to BookTrail

## Branch Naming Convention

Use the following format:

`<type>/<short-description>`

Examples:

- `feature/navbar`
- `feature/book-search`
- `bugfix/login-validation`
- `hotfix/build-error`
- `docs/update-readme`

Rules:

- Use lowercase letters.
- Separate words with hyphens.
- Use a meaningful, short description.

## Commit Message Convention

Follow the Conventional Commits format:

`<type>: <description>`

Supported types:

- `feat`: Add a new feature
- `fix`: Fix a bug
- `docs`: Documentation changes
- `style`: Styling or formatting changes
- `refactor`: Code restructuring
- `test`: Add or update tests
- `ci`: CI/CD configuration changes
- `chore`: Maintenance tasks

Examples:

- `feat: add navigation bar`
- `fix: resolve login validation`
- `docs: update project readme`
- `ci: update workflow triggers`

Rules:

- Use lowercase type prefixes.
- Keep descriptions clear and concise.
- Use imperative wording where practical.
- Do not end the description with a full stop.
